# wxbot — 微信自动回复桌面助手（安全优先）

给**个人微信**做「自动回复好友 / 群消息」的 Windows 桌面小工具。
一句话原则：**安全网关当守门员，宁可少回，不可冒进。**

> 免责声明：微信官方不支持任何第三方自动化。本项目只使用「不侵入微信进程」的技术
> （WGC 后台抓屏 / OCR / 键鼠模拟 / UIA 只读），并按拟人化策略运行；即便如此仍存在
> 账号受限的小概率风险 —— 请用日常老号、保持低频，风险自负。

## 当前进度（v2.5.0）

- ✅ **修好"模型连不上时无限重试"**：以前生成失败**不计入熔断**（`note_failure` 只在发送失败时调用），
  也没有重试上限，于是同一条消息每 34 秒重试一次直到天荒地老。现在按「会话+文本」记住处理进度：
  拦截 / 跳过 / 发送失败是终态不再重复；生成失败退避重试，**3 次后明确记录放弃**（新消息照常处理）
- ✅ **修好"程序刚启动就把已答过的消息又回一遍"**：气泡换行时续行在气泡内左对齐，
  一条右对齐的绿色气泡**第二行的中心会掉到中线左边**。现在先把换行的几行**合并成一条气泡**再判方向；
  判"我发的"要同时满足"右缘够靠右"和"左缘不在对方起点"，判不准就不回（**宁可漏回，绝不乱回**）
- ✅ **修好"点一下「获取模型列表」就把勾选的「图片」弄掉"**：现在只有当前模型真的换了才会预填
- ✅ **修好"本地模型一律被当成不支持图片"**：本地厂商不再直接返回"纯文本"把整张规则表短路
- ✅ **修好"人设失效、暴露 AI 身份"**：「不许暴露 AI」改成永远追加在末尾的硬性规则（用户改不动）
- ✅ **修好"AI 没记忆"**：会话名归一化后再入库；入库前清洗脏文本

## 性能

一轮轮询的耗时分布（811x565 窗口，5 轮平均，实测）：

| 环节 | 优化前 | 优化后 |
| --- | --- | --- |
| 抓屏（WGC） | 181 ms | 181 ms |
| 读标题 | 601 ms | **124 ms** |
| 读聊天气泡 | 333 ms | 235 ms |
| 读会话列表 | 258 ms | **144 ms** |
| **整轮 poll** | **1175 ms** | **596 ms** |

轮询间隔占用率从 39% 降到 20%。

**关键优化：OCR 区域补白。** RapidOCR 预处理时会把输入的**短边**放大到
`limit_side_len`（默认 736），于是"扁长"区域被成倍放大 —— 标题栏 320x45
（长宽比 7:1）要 575ms，补白成正方形只要 105ms。**慢的是凭空多出来的空白，
跟像素量无关**：320×320 反而比 320×45 快 5.5 倍。

```powershell
.\.venv\Scripts\python.exe tools\profile_cycle.py        # 各环节耗时
.\.venv\Scripts\python.exe tools\profile_ocr_region.py   # 补白前后对比
```

### 用 qwen/qwen3.5-9b 的话，超时要给到 600 秒

`❌ 生成失败：…：timed out` **不是程序卡住，是模型在思考**。LM Studio 日志长这样：

```
n_gen = 578, tg = 13.14 t/s          ← 速度很健康
"content": "",                        ← 但正文一直是空的
"reasoning_content": "Thinking Process: …"   ← 585 个思考 token 了还没完
[LM STUDIO SERVER] Client disconnected. Stopping generation...
                                   ↑ 这一行是**我们自己的超时**踢的
```

**这个模型关不掉思考**，能试的写法全试过：

| 写法 | 结果 |
| --- | --- |
| `chat_template_kwargs: {"enable_thinking": false}` | **参数被 LM Studio 收下了，模型照想不误** |
| 顶层 `enable_thinking: false` | 无效 |
| 提示词末尾加 `/no_think`（Qwen3 老办法） | 无效，新版不认 |
| `reasoning_effort` | 无效 |

**只能等。** 四次实测（走完整流水线）：

| 消息 | 耗时 | 思考量 | 结果 |
| --- | --- | --- | --- |
| 你好 | 167 s | 2167 token | ✅ `你好呀～ 在呢，咋啦？😄` |
| 你是谁 | 196 s | 2530 token | ✅ 完整人设答对 |
| 你好 | 78 s | 3343 字 | ✅ `你好呀～在呢！😊👋` |
| 你是谁 | **291 s** | 12906 字 | ✅ 完整人设答对 |

**波动极大：78 ~ 291 秒。** 慢的那次距 300 秒超时只剩 9 秒，
所以「请求超时」要设 **600 秒** 才保险。

> ⚠ **代价要知道**：一条微信要等 1~5 分钟，而且**快慢全看模型当天想多久**。
> 生成期间主循环是**阻塞**的，这段时间不识别新消息。
>
> 对照同一份 LM Studio 日志：`gemma-4-e2b` 不思考时**总共只用 503 毫秒**，
> `minicpm-v-4.6` 是 2~3 秒。差的不是显卡，是"要不要思考"。

## 运行页：上下文窗口占用 + 模型思考过程

「运行」页指标卡下面有一张**上下文窗口**卡片：

- **占用条**：`prompt_tokens / context_length`，用颜色分级 ——
  <70% 蓝、≥70% 橙、≥90% 红。上下文快满时模型会开始答非所问甚至直接报错，
  这时该去「技能」页把「对话记忆」的条数调小。
- **最近一次思考过程**：点标题展开。思考型模型（qwen3.5 / o 系列）会先想几十秒才吐字，
  展开就能看到它到底在想什么，而不是干等着以为程序卡死了。
  实时日志里也会用 `🧠` 打一行思考摘要。

数据链路：模型返回的 `usage.prompt_tokens` → `LLMResult` → `PipelineResult` →
`RunnerStats` → 界面。Claude 走 `input_tokens`/thinking 块，已一并适配。

自检：`tools/check_context_usage.py`（用真实模型响应验证用量解析）、
`tools/shot_run_context.py`（截三种状态：空闲 / 正常 / 快满告警）。

## 记忆体检

对话记忆会把**之前的回复当成 few-shot 示例**喂回给模型，所以脏数据会直接教坏模型。

```powershell
.\.venv\Scripts\python.exe tools\check_memory_hygiene.py     # 体检：泄露身份 / 截断半句 / 重复
.\.venv\Scripts\python.exe tools\clean_memory.py             # 预览清理
.\.venv\Scripts\python.exe tools\clean_memory.py --apply     # 执行（自动备份）
```

会清理三类：**自称助手/AI 的旧回复**（必须删，否则模型跟着学）、
**换行气泡被拆开的截断半句**、**生成失败重试时重复记入的同一条消息**。

程序侧也已修正：**只有真的产出回复了才写记忆**，失败重试不会再把消息一遍遍塞进去。

## 记忆（AI 的"上下文记忆"）

程序会把每个会话的往来消息记进 `data/chat_memory.json`，回复时把**最近 N 条**
（默认 12，可在「技能」页调整）作为上下文一起发给模型。

两个容易踩的坑（都已修）：

1. **会话名必须归一化**——OCR 有时把「老王！」读成「老王!」。如果直接用原始名作 key，
   同一段对话会被劈成两份记忆，模型每次只看到一半，于是"完全不记得说过什么"。
2. **入库前清洗文本**——会话摘要里会混进未读角标数字（"…父亲吗 3 3"）和时间前缀（"17:32 你好"）。

想清掉或整理记忆：

```powershell
.\.venv\Scripts\python.exe tools\migrate_memory.py              # 合并 + 清洗（保留内容）
.\.venv\Scripts\python.exe tools\migrate_memory.py --drop 某人    # 顺便清掉某个会话
.\.venv\Scripts\python.exe tools\check_memory_context.py         # 自检：历史是否真的用上了
```

> 注意：**模型越大，多轮记忆越稳**。`minicpm-v-4.6` 只有 752M 参数，能用上下文但容易
> 忘事；换 `Qwen3-8B` 之类会明显好很多。
- ✅ **消息内容更准**：当前会话改读聊天区完整气泡（会话列表摘要会被截断）
- ✅ 修复未读角标数字被误当会话名（曾导致整行会话被丢弃）
- ✅ **滚轮防误操作**：下拉框/数字框/滑块不再被滚轮误改；短文本框把滚动交回页面
- ✅ **人设页面**：他是谁 / 说话方式（语气·正式度·长度·表情）/ 语言习惯（口头禅·禁忌），
  带**实时预览**与「试生成一条回复」
- ✅ **真实收发打通**：抓屏识别 → 安全网关 → 生成 → 切会话 → 校验标题 → 输入 → 回车 → 校验已发出（实测发送成功）

- 🎨 **界面**：侧边导航 + 卡片式布局 + 滑动总开关 + 指标卡 + 彩色日志；深色（默认）/ 浅色可切换

## 运行开关（核心交互）

图形界面「运行」页最上方就是总开关：

- **点「▶ 启动（开始识别微信）」** → 才开始抓屏识别微信会话、走安全网关与回复流水线；
- **点「■ 停止」** → 立即停工，不再抓屏、不再识别、不执行任何后续动作；
- 下方实时显示：状态、轮询/识别/拟回复/已发送/拦截/跳过/出错 计数，以及本次运行的日志；
- 识别间隔可调（默认 3 秒；越短越灵敏，抓屏越频繁）；
- **关闭窗口会自动停机**，不会留下在后台偷偷跑的线程。

命令行等同操作：`python -m wxbot run`（Ctrl+C 停止，`--interval 5` 可调间隔）。

> 当前发送能力已接入：模式为「全自动」时，识别到白名单内的新消息会**真实发送**回复。
> 发送前有四道保险：① 安全网关（白名单/静默/限速/熔断）；② 切换会话后校验聊天标题；
> ③ 输入后确认输入框确实有文字；④ 发送后抓屏确认消息已出现。任一步失败即中止，不盲发。

## 滚轮行为（避免误操作）

滚轮划过界面控件时的规则：

| 控件 | 行为 |
| --- | --- |
| 下拉框（厂商 / 语气 / 模型…） | **不会**因滚轮改变选中项；滚轮转交给页面 |
| 数字框（各种上限/数量） | **不会**因滚轮改变数值 |
| 滑块（正式程度） | **不会**因滚轮改变 |
| 短文本框（内容装得下） | 不在框内滚动，滚轮转交页面（避免"悬停在输入框上整页滚不动"） |
| 长文本框（内容溢出） | **仍然先滚页面**；页面到顶/到底后才在框内滚（要看长内容时需要） |
| 表格（模型库 / 自学习列表） | 滚轮滚表格自身（这是列表的正常行为） |

**⚠ 为什么文本框不能"内容溢出就自己滚"（v2.6.2 修，用户报的闪动 bug）**：
内容是在**光标底下**移动的。滚一下页面，光标下就换成了另一个内容溢出的文本框；
下一格滚轮它就抢走，页面纹丝不动；再滚一下又变回页面……
两个滚动条交替接管，视觉上就是"滚动窗口就闪"。

规则因此改成**单向**：只要页面还能滚就滚页面，页面到顶/到底了才给文本框。
行为固定下来，就不会有交替，也就不会闪。

配套修复：页面到底时 `setValue` 会被 Qt **静默钳位**（值没变），
旧代码只要找到滚动条就返回"成功"，于是事件被吞掉、文本框永远拿不到滚轮。
现在**只有滚动条真的动了才返回成功**。

实现见 `gui.py: _NoWheelFilter`；自检脚本 `tools/check_gui_wheel.py`、
`tools/check_model_page_wheel.py`，单测 `tests/test_gui_wheel.py`。

## 消息检测（三种信号，缺一不可）

| 信号 | 覆盖 | 盲区 |
| --- | --- | --- |
| **未读红点** | 会话列表里未打开的会话 | **会话正打开时微信不显示红点** |
| **摘要变化 / 新会话冒头** | 大多数情况 | 摘要可能被截断；连续多条消息时摘要不变 |
| **当前打开的会话**（读气泡） | 你正看着的那个会话 | 需要该会话在列表里 |

**怎么判断"这条是谁发的 / 需不需要回"**：
1. **发送方**：靠气泡的**左右位置**——对方靠左、自己的靠右（绿色气泡），
   用相对中线的比例判定，窗口任意大小都成立；
2. **要不要回**：**当前会话最后一条气泡是对方发的 = 还没回**。
   这比"和上一轮比差异"稳健得多 —— 差分会漏掉程序启动前就存在的未回消息
   （实测踩过：会话正开着 → 没有红点 → 又被基线跳过 → 永远不回复）。
3. 同一条消息只上报一次（`_claimed_text` 认领 + `_last_replied_text` 发送后更新）。

其它两个信号（会话行未读红点、摘要变化）用于覆盖**没打开**的会话。

启动时第一轮只建立基线、不回复（避免启动瞬间把旧消息全回一遍）；下一轮开始处理
（约等于一个识别间隔，默认 3 秒）。

> **如果你自己手动点开某个会话看过了**，红点就没了，程序不会补回 —— 这是有意的，
> 避免对你已经处理过的人重复打扰。

## 封号风险自评估（诚实版）

**结论：以本项目的做法，风险低但不为零。真正该担心的不是"被识别为自动化"，而是"行为像营销号"。**

不碰微信进程 —— 这点可以自证：

| 检测面 | 本项目 | 说明 |
| --- | --- | --- |
| 内存读写 / DLL 注入 / Hook | ❌ 没有 | 源码里搜不到 `WriteProcessMemory`/`CreateRemoteThread`/`SetWindowsHookEx` 等 |
| 私有协议 / 改包 / 模拟客户端 | ❌ 没有 | 网络侧就是官方客户端在通信 |
| 读取聊天内容 | 只读屏幕像素 | WGC 截图 + OCR，微信进程无感知 |
| 发送消息 | 模拟键鼠 | 点击 + 剪贴板粘贴 + 回车，等同人在操作 |

行业调研的共识：封号案例集中在**批量群发、自动加人、协议模拟、Hook 注入**；
纯界面自动化在"低频、个人使用"场景下几乎没有封号报告（风险档位：UI 自动化低~中，
Hook 中高，协议模拟高/极高）。

**剩余的真实风险（按重要性）**：

1. **行为特征**：秒回、24 小时在线、回复频率异常、内容重复 → 可能触发风控，
   更可能被好友**举报**（举报是最现实的封号路径）。
2. **输入事件的技术特征**：`SendInput` 注入的事件带"注入"标记，理论上可被检测；
   公开资料中没有因模拟输入而被判外挂的实例（这与屏幕阅读器/宏按键同类）。
3. **循环/刷屏**：本项目曾出现"自问自答死循环"（已修复）——这类异常行为最危险。

**已经内建的降低特征措施**：

- 回复随机延迟 2~6 秒（可调）；静默时段 23:00–08:00；每分钟/小时/天三级限速；连续失败自动熔断
- 点击坐标**随机抖动 + 平滑移动**（不再对同一像素瞬移点击）
- 粘贴后按文本长度停顿再回车（模拟打字节奏）
- 白名单外一律不回；群聊默认只在被 @ 时回；绝不主动发起对话

**建议进一步加固（尚未默认开启，可按需加）**：偶尔"不回复"（如 10% 概率跳过）、
连续回复若干条后暂停几分钟、只在你的活跃时段运行、每天总量上限再收紧。

**想把风险压到接近零**：换结构 —— 另一台电脑/另一个 Windows 用户会话、虚拟机，
或用官方渠道（企业微信「微信客服」API，不碰界面，但非个人微信身份）。

## 关于「会不会抢前台和鼠标」（重要）

**读取**用的是 WGC，完全在后台，不会打扰你。**写入**（点击、输入）受 Windows 限制，
需要目标窗口拿到真实焦点。实测结论（见 `tools/experiment_background_*.py`）：

| 操作 | 后台（不置前）可行？ |
| --- | --- |
| 投递鼠标点击（PostMessage） | ✅ 可行：能切换会话，且光标不动 |
| 投递字符键（WM_CHAR） | ❌ 不可行：微信输入框只接受真实键盘输入 |

所以打字这一步绕不开"短暂置前"，但已经把打扰降到最低：

1. **发送前先等你停手**：你 1.5 秒内有键鼠操作就等一等（最多 8 秒，超时则跳过本次发送）；
2. **目标会话已经打开时，跳过"点会话行"**，少一次点击；
3. **用剪贴板粘贴**（只 2 次按键），不逐字敲键盘；
4. **发完立刻还原**你的鼠标位置与原来的前台窗口（实测：前后光标与前台窗口完全一致）。

想要**彻底零打扰**，只能换结构：

- 把「微信 + wxbot」放在**另一个 Windows 用户会话 / 另一台电脑**上跑（最实用）；
- 或用**虚拟机**；
- 或走**官方渠道**（企业微信「微信客服」API）——完全不碰界面，但那是企业身份、不是个人微信。

## 性能与"卡住"排查（实测记录）

已修掉的三个导致"连续发送卡住"的原因：

| 原因 | 现象 | 修复 |
| --- | --- | --- |
| 抓屏等"收集 3 帧" | **每次抓屏卡 9 秒**（静止窗口只出 1 帧，等不到就等满超时）；一次发送要抓 5~6 次 → 单个回复 40 秒+ | 改单帧抓屏：**0.17 秒/次** |
| 自问自答死循环 | 自己发的消息出现在会话摘要里，被当成新消息 → 反复回复自己 | 发送后记录已发内容，轮询时跳过；会话标识归一化 |
| 每分钟限速 | 一分钟内第 3 条起被拦（日志显示"超过每分钟限额"） | 按需在「回复与速度」页调大上限 |

排查手法：`tools/debug_session_panel.py`（未读检测）、以及直接给抓屏/OCR 分步计时。
抓屏耗时可直接用下面的片段量：

```powershell
.\.venv\Scripts\python.exe -c "import time; from wxbot.wechat.capture import grab_bgr, find_main_window; h=find_main_window()['hwnd']; t=time.time(); grab_bgr(h); print(f'{time.time()-t:.2f}s')"
```

### 「系统提示词」和「人设」别打架

两者都会进同一条系统提示词，**写在后面的优先级更高**。最终顺序固定为：

```
默认提示词  →  「系统提示词」（留空则跳过）  →  各技能（人设/安全/群聊/学习）
             →  硬性规则（永远最后，用户改不动）
```

- **日常只需要改「人设」页**，模型页的系统提示词留空即可。
- 唯一必须靠系统提示词写的，是"跟身份无关的通用要求"（例如"回复用简体中文"）。
- **千万别在系统提示词里写"你是……助手 / 机器人 / AI"**——那会让人设自曝身份。
  程序检测到这类字眼会当场弹橙色警告，帮你定位。

自检脚本：`tools/check_sys_prompt_conflict.py`（验证配置已清空 + 冲突能被实时发现 +
硬性规则确实排在最后）。

**主题**：右上角按钮一键切换深色 / 浅色，选择会记进 `config.toml` 的 `[ui]` 段。

## 多厂商模型管理

内置 19 个厂商预设（见 `python -m wxbot providers`）：

| 类别 | 厂商 |
| --- | --- |
| 国内 | DeepSeek、Moonshot Kimi、智谱 GLM、通义千问（百炼）、豆包·火山方舟、MiniMax、腾讯混元、硅基流动、百川、零一万物 |

| 本地 | LM Studio、Ollama |
| 兜底 | 自定义 / 其它 OpenAI 兼容服务 |

**每个厂商里的每个模型都能单独配置**（存在 `data/models.json`）：

- **上下文长度**：该模型可用的最大上下文
- **输入模态**：文本 / 图片 / 音频 / 视频 / 文件（勾选）
- **思考等级**：auto / 关闭 / 低 / 中 / 高（本程序会自动翻译成各厂商的对应参数）

选厂商时**地址与 Key 配置会自动填好**，无需额外点击（手改过想恢复默认，用「重置为厂商默认」）。

**自动识别**：点「从厂商获取模型列表」时，会按模型名自动匹配元数据库并预填上述参数
（例如 `gpt-5-*` → 400k 上下文 + 图片 + 思考默认中；`gemini-2.5-*` → 1M + 全模态；
`qwen3-*` → 默认关闭思考）。预填只是默认值，随时可手改，也可点「按名称重新自动填充」。

**切换模型的三种方式**：
1. 直接点模型下拉框选择（启动时已自动列出该厂商已配置的模型）；
2. 切换厂商，下拉框会自动换成新厂商的模型；
3. 手动输入模型名（任何名字都行，比如云端自定义部署的模型）。

思考等级的落地方式随厂商而异（程序自动处理）：OpenAI 传 `reasoning_effort`；
Claude 传 `thinking.budget_tokens`；百炼 / 方舟 / 智谱 / 硅基流动等传 `enable_thinking`；
Qwen3 关闭思考时自动加 `/no_think`。

## 人设（决定 AI 是谁、怎么说话）

左侧**「人设」**是独立页面，分四块：

| 区块 | 能设置什么 |
| --- | --- |
| **他是谁** | AI 扮演的身份（姓名、职业、年龄、性格…） |
| **说话方式** | 语气（自动/温和/中性/干脆/幽默）、正式程度（滑块 0~100）、回复长度（很短/短/中等）、表情符号（不用/偶尔/经常）、说话风格补充 |
| **语言习惯** | 常用口头禅、绝对不要做的事 |
| **预览** | **实时显示 AI 实际收到的人设指令**（改一个字立刻更新），还能「试生成一条回复」看实际效果 |

预览与实际注入用的是**同一个函数**（`brain/skills.py: build_persona_prompt`），
所以你在预览里看到的就是模型真正收到的内容，不会"预览一套、发出去另一套"。

配置落在 `config.toml` 的 `[skills.persona]`：`identity` / `tone` / `formality` /
`length` / `emoji` / `catchphrases` / `avoid`。空字段不会写进提示词。

### ⚠️ 「不许暴露 AI 身份」是硬性规则

这条**不放在**可编辑的"系统提示词"里，而是**永远追加在提示词末尾**
（`brain/skills.py: MANDATORY_RULES`）。原因：早期把它写进默认提示词，
用户一自定义就容易写成「你是代回复助手，但不要暴露身份」这种**自相矛盾**的话，
模型就会自曝身份。现在措辞是"哪怕前面的设定里这样写过，也一律不采纳"。

自检：

```powershell
.\.venv\Scripts\python.exe tools\check_persona_identity.py      # 问"你是谁/你是AI吗"看是否泄漏
.\.venv\Scripts\python.exe tools\compare_persona_models.py     # 对比不同模型的人设遵循能力
```

> **模型越大，人设越稳**。实测 `minicpm-v-4.6`（752M）会有时漏一句，
> `gemma-4-e2b`（4.6B）三问全部照人设回答。

## 自学习技能（AI 复盘）

程序运行中会把每个会话的往来消息记进本地记忆（`data/chat_memory.json`，需开启「对话记忆」）。
可以让 AI 复盘这些记录、自动整理成技能条目（存 `data/learned_skills.json`）：

- **问答习惯（faq）**：「对方说什么 → 我一般怎么回」的规律，回复时按关键词参考
- **会话备注（note）**：某个会话的背景（对方是谁、聊什么、注意什么），只对该会话生效
- **风格补充（style）**：从实际回复中总结的说话风格，全局生效

触发方式：

- 图形界面「技能」页 → **立即学习（分析最近聊天）** 按钮
- 命令行：`python -m wxbot learn`（可加 `--chat 名称` 只看某个会话）
- 自动学习：GUI 可设置「每 N 条真实回复自动整理一次」（主循环接入后生效）

所有条目都会显示在 GUI 列表里，**逐条勾选启用/停用**；学习产物只作为提示词参考，
永远不会被直接照发。学习效果随实际收发积累越来越好（需要先配置模型）。

## 技术路线（调研结论）

- 微信 4.x 起客户端自绘渲染，传统控件树自动化（wxauto 等）失效；
- 实测结论：UIA 只能读到窗口框架层；聊天内容必须走视觉路线；
- 抓屏方案实测：直接截屏（被遮挡失效）❌、PrintWindow（全黑）❌、
  **WGC（windows-capture）✅ 被遮挡也能稳定读取**；
- OCR 用 RapidOCR（离线），对微信界面中文识别质量很好；
- **明确排除**：Hook 注入、内存读写、协议逆向（封号高危，绝不采用）。
